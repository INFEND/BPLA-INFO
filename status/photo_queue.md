# БПЛА ИНФО: очередь восстановления фотографий

Последняя проверка: 2026-11-02 19:27 UTC. Ветка `main`. Последний APK Release: v1.0.11; новые изменения исходников не выпущены.

## Подтверждено
- Основной каталог: 87 моделей; `photo_sources.json` содержит 16 моделей и 60 ссылок на файлы Wikimedia Commons.
- Полные по **количеству ссылок** (5): 9 моделей. Неполные (1–4): 7. Без ссылок: 71. Это НЕ оценка реально работающих галерей.
- В GitHub Actions 41500291912 на предыдущем манифесте 6 из 61 URL ответили HTTP 200 image/*, 55 проверок были заблокированы HTTP 429 (в том числе Retry-After 600 секунд). Это были проверки HEAD, а не декодирования на Android. Прежний зелёный результат не означал успешной проверки всех изображений.
- В исходниках исправлены проверка декодируемости кэша и скачанного файла, нулевая высота полноэкранного просмотра и отсутствие видимой индикации ошибки/загрузки. Очередь загрузки теперь отдаёт приоритет полноэкранным фото при сохранении одного сетевого рабочего потока; в полноэкранном просмотре добавлены статус и повтор по нажатию. Android-клиент учитывает числовой Retry-After (до 15 секунд) и не повторяет запросы немедленно при длинной блокировке. Проверка на физическом Android пока не выполнена.
- Достоверность модели и лицензию нельзя подтверждать только по имени файла. Для UJ-22 и EOS C проверены страницы Commons с указанными авторами и CC BY-SA 4.0. Дополнительно вручную проверены 4 страницы FlyEye (Krzysztof Popławski, CC BY 4.0), добавлены точные ссылки и метаданные. Смешанный снимок FlyEye/Warmate RR удалён из галереи FlyEye; 4 отдельные фотографии оставлены. Доступность Android-загрузки и различимость ракурсов по пикселям пока не доказаны.

## Очередь по приоритету
1. Устранить сетевые блокировки Wikimedia при проверке (403/429/503/тайм-ауты). Строгая проверка пока не пройдена: GitHub-hosted runner получает Retry-After 600 секунд. Проверить Actions 41509871598, затем подтверждать GET изображения, MIME, разрешение и декодирование. Не считать HTTP HEAD подтверждением Android-галереи. **Не** принимать блокировку за успех.
2. Протестировать реальную загрузку на Android: 5 фото в карточке, полноэкранный просмотр, повторный вход, офлайн-кэш, битый файл кэша, отсутствие сети.
3. Для 60 записей собрать и сверить страницу Commons, автора, лицензию, реальное содержимое и разные ракурсы. Недостоверные или несуществующие записи исправлять только после проверки.
4. Закрыть 7 частичных галерей и 71 модель без фотографий, используя 3–5 лицензированных реальных снимков, если доступны. Сохранять отметку «неполное покрытие», когда подходящих снимков меньше.
5. Добавить отдельный подписанный/хешированный версионируемый каталог изображений с проверкой SHA-256 и ограниченным Android-кэшем. Не использовать приватные API или секреты в APK.
6. После подтверждённой сборки и проверки изображений выпускать отдельный APK-релиз с новым versionCode/versionName; до этого не публиковать непроверенный хотфикс.

## Правило отчётности
`Photo sources integrity` должен завершаться ошибкой, если хоть одна ссылка недоступна для проверки. Это состояние **INCONCLUSIVE**, а не доказательство отсутствия файла. Отдельно учитывать `MISSING` (подтверждённая ошибка URL).
