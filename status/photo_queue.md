# БПЛА ИНФО: очередь восстановления фотографий

Последняя проверка: 2026-11-02 UTC. Ветка `main`.

## Подтверждено
- Основной каталог: 87 моделей; `photo_sources.json` содержит 16 моделей и 61 ссылку на файлы Wikimedia Commons.
- Полные по **количеству ссылок** (5): 10 моделей. Неполные (1–4): 6. Без ссылок: 71. Это НЕ оценка реально работающих галерей.
- В GitHub Actions 41492184151 до исправления проверки только 2 из 61 ссылок ответили как доступные; 59 имели сетевые блокировки/ошибки. Прежний зелёный результат не означал успешной проверки всех изображений.
- В исходниках исправлены проверка декодируемости кэша и скачанного файла, нулевая высота полноэкранного просмотра и отсутствие видимой индикации ошибки/загрузки. Проверка на физическом Android пока не выполнена.
- Достоверность модели и лицензию нельзя подтверждать только по имени файла. Для UJ-22 и EOS C проверены страницы Commons с указанными авторами и CC BY-SA 4.0; доступность Android-загрузки пока не доказана.

## Очередь по приоритету
1. Устранить сетевые блокировки Wikimedia при проверке (403/429/503/тайм-ауты). Уже добавлены задержка между запросами, повтор при 429 и строгая обработка неопределённого результата; проверить итоговый прогон Actions, затем подтверждать GET изображения, MIME, разрешение и декодирование. **Не** принимать блокировку за успех.
2. Протестировать реальную загрузку на Android: 5 фото в карточке, полноэкранный просмотр, повторный вход, офлайн-кэш, битый файл кэша, отсутствие сети.
3. Для 61 записи собрать и сверить страницу Commons, автора, лицензию, реальное содержимое и разные ракурсы. Недостоверные или несуществующие записи исправлять только после проверки.
4. Закрыть 6 частичных галерей и 71 модель без фотографий, используя 3–5 лицензированных реальных снимков, если доступны. Сохранять отметку «неполное покрытие», когда подходящих снимков меньше.
5. Добавить отдельный подписанный/хешированный версионируемый каталог изображений с проверкой SHA-256 и ограниченным Android-кэшем. Не использовать приватные API или секреты в APK.
6. После подтверждённой сборки и проверки изображений выпускать отдельный APK-релиз с новым versionCode/versionName; до этого не публиковать непроверенный хотфикс.

## Правило отчётности
`Photo sources integrity` должен завершаться ошибкой, если хоть одна ссылка недоступна для проверки. Это состояние **INCONCLUSIVE**, а не доказательство отсутствия файла. Отдельно учитывать `MISSING` (подтверждённая ошибка URL).
